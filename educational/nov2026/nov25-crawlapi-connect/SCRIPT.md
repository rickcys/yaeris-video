## Full script (verbatim, 8 lines)

1. Adding a scraping layer to an existing system sounds like it means standing up a brand-new backend service. Usually it doesn't have to.
2. There are two fundamentally different ways a scraping tool can integrate, and only one of them adds real infrastructure weight.
3. The fear: new service to deploy, new infrastructure to maintain, a proprietary SDK your team has to learn from scratch.
4. The actual pattern here: one API key, standard REST responses your existing backend already knows how to parse, or the exact same key through MCP for an agent.
5. The test is simple -- check whether adopting a given tool requires a new service, or just a new API key dropped into what you already have running.
6. Crawl API returns standard JSON over a normal REST call, no proprietary SDK, and the same key works through MCP if you're building with an agent instead.
7. A scraping layer that needs its own standalone infrastructure isn't actually simplifying anything. It's just moving the complexity somewhere else.
8. Follow for more of this kind of content.
