Building something genuinely useful
in the MCP ecosystem doesn't
mean people actually find it.
That's a separate, much less
glamorous problem.
There are two fundamentally different paths
from built it to someone's
using it, and most new
projects only get the
benefit of one.
Organic discovery. Someone stumbles across
a GitHub repo, maybe sees
a post about it once,
and that's the entire discovery
funnel. Real, but almost entirely
luck-dependent.
Directory Discovery. Indexed by category
and server type, searchable by
the exact person already looking
for a tool like it,
no luck required.
The tell is simple. Look
at where your current installs
are actually coming from, a
direct link someone already had,
or an actual search that
led a stranger to you.
This is the category DReview
is built into. Free to
list, no expiration, searchable by
category and server type, and
editable anytime after approval, so
the listing stays current as
the project evolves.
Quality and visibility are genuinely
two separate problems. Solving the
first one doesn't automatically solve
the second.
