1. Building something genuinely useful in the MCP ecosystem doesn't mean people actually find it. That's a separate, much less glamorous problem.

2. There are two fundamentally different paths from "built it" to "someone's using it," and most new projects only get the benefit of one.

3. Organic discovery: someone stumbles across a GitHub repo, maybe sees a post about it once, and that's the entire discovery funnel. Real, but almost entirely luck-dependent.

4. Directory discovery: indexed by category and server type, searchable by the exact person already looking for a tool like it, no luck required.

5. The tell is simple: look at where your current installs are actually coming from -- a direct link someone already had, or an actual search that led a stranger to you.

6. This is the category DReview is built into -- free to list, no expiration, searchable by category and server type, and editable anytime after approval, so the listing stays current as the project evolves.

7. Quality and visibility are genuinely two separate problems. Solving the first one doesn't automatically solve the second.
