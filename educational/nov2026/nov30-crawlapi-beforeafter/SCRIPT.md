## Full script (verbatim, 8 lines)

1. Same scraping project, same end goal, wildly different amount of time spent just keeping it alive.
2. There are two fundamentally different maintenance burdens behind that same project.
3. Before: a custom scraper that breaks the moment a target site adds rate-limiting or starts needing real JavaScript rendering, and nobody notices until the data's already missing.
4. After: one API call that handles that same escalation automatically, and publishes a real, honest success rate instead of leaving you to discover failures after the fact.
5. The test is counting actual hours spent on scraper maintenance in a typical month, before versus after switching to something that handles the escalation itself.
6. That automatic three-tier escalation, direct fetch to proxy to headless browser, covers exactly the failure modes that used to require someone manually fixing things.
7. The project itself never changed. The tax of keeping the old version alive just disappeared.
