A scraping API working perfectly
on your first test page
tells you almost nothing about
whether it's actually production ready.
There are two fundamentally different
ways a scraper handles a
target site, and the difference
only shows up once that
site fights back.
The naive scraper, one fetch
method every time, works fine
on simple static pages.
The moment it hits rate
limiting or a page that
needs real JavaScript rendering,
it either gets blocked or
comes back with an empty shell,
no error, just nothing.
The escalating scraper tries a
simple direct fetch first and
automatically upgrades to a residential
proxy, then a full headless
browser, only when it
actually needs to,
with no manual configuration
deciding which path to take.
The tell is simple. Point
it at a genuinely JavaScript
heavy page and see what
actually comes back. A real
answer or an empty shell.
